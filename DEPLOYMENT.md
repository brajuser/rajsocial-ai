# RajSocial AI — managed MCP deployment (Render)

This package adds a Render Blueprint for deploying the MCP queue service with HTTPS, a persistent disk, and a host-generated bearer secret. The server only manages draft queue/profile data; it does not log in to Reddit/Quora or publish posts.

## Deploy to Render

1. Put the `rajsocial-ai` folder in a private GitHub repository. Do not commit `.env` files, real API keys, passwords, browser cookies, or session tokens.
2. Sign in to Render and choose **New → Blueprint**. Connect that private repository and select `render.yaml` at the repository root.
3. Review the Blueprint. It creates a paid Starter web service and a 1 GB persistent disk; persistent disks are used so queue data survives redeploys. Confirm pricing in Render before creating it.
4. Render generates `MCP_BEARER_TOKEN` as a secret environment variable. Do not copy it into source code, the Chrome extension, screenshots, or chat. If you need to rotate it, use the Render dashboard's environment settings and redeploy.
5. After deploy, open the service URL plus `/health`. Expected response resembles `{"ok":true,"service":"rajsocial-ai-mcp","publishingEnabled":false}`.
6. The MCP endpoint is `https://YOUR-SERVICE.onrender.com/mcp`. Keep the endpoint URL; never publish the secret.

## ChatGPT connection caveat (important)

A deployed endpoint does not automatically connect to ChatGPT. ChatGPT custom MCP support depends on the account plan and workspace settings. Current OpenAI documentation says full MCP/write support is rolling out to Business, Enterprise, and Edu; Pro supports read/fetch custom MCP in developer mode, while other plans/workspaces may not expose custom MCP connection controls. This account currently appears to be on ChatGPT Go, so check whether **Settings → Apps** or the ChatGPT **Plugins / Add custom MCP server** flow is available before paying for hosting.

The server currently uses a bearer token, not OAuth. Use it only with an MCP client/connection flow that explicitly supports a bearer-token/API-key header. If ChatGPT's connection UI requires OAuth, do not select "No authentication" as a workaround. We should implement OAuth or choose a supported secure tunnel/client before connecting it. Never disable the token on a public endpoint.

## Security notes

- `MCP_BEARER_TOKEN` is generated by Render; do not store it in Git.
- Do not put secrets in the Chrome extension (all extension code is visible to the user).
- HTTPS is provided by the hosting platform.
- The queue file lives on `/var/data/data.json` on a persistent disk.
- The `/health` endpoint intentionally reveals only service health.
- MCP tools can read/edit the queue, but cannot publish, vote, comment, or access account credentials.
- The saved guideline text is a checklist, not a live policy feed. Verify actual community rules before posting.
- Do not use this tool for repetitive karma farming, mass cross-posting, or evasion of community rules.

## Local test

Requires Node.js 20+.

```bash
cd mcp-server
npm install
HOST=127.0.0.1 npm start
```

Local endpoint: `http://127.0.0.1:8787/mcp`
Health: `http://127.0.0.1:8787/health`

## Before production

- Confirm current Render pricing and persistent disk limits.
- Verify `/health` over HTTPS.
- Test with non-sensitive sample drafts.
- Confirm the client supports the authentication scheme before connecting.
- Do not add Reddit/Quora OAuth until you have official API access and have reviewed the current platform developer terms.
